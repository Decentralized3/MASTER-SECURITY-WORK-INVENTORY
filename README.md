# Decentralized3 — Repository Overview

This index gives the GitHub account a coherent structure without turning every repository into a claim of professional security experience.

The account contains several kinds of work:

1. Security research and testing
2. Security tooling and automation
3. Android/mobile experimentation
4. Software engineering
5. Learning and laboratory work
6. Private projects under development

## How the work is presented

The standard is:

> Document what was actually done, show what was actually built, state what happened, and be explicit about what remains unfinished or private.

A repository is not treated as evidence of a capability merely because its name suggests one.

An experiment that produced a useful negative result can be documented, but it is not rewritten as a successful exploit or completed project.

## Public vs private

Private repositories may contain work that is useful to the professional record but is not yet suitable for publication.

Reasons can include active development, unfinished implementation, sensitive target information, disclosure restrictions, security-sensitive operational details, or the need to separate research from public release.
