# Security Work

A technical record of security work completed, practiced, tested, and investigated over time.

This is not a list of claimed skills. Each entry is written around the actual work:

**context → objective → work performed → result → lesson → current status**

The repository also preserves useful unsuccessful experiments when the failure itself produced a technical lesson.

## How entries are written

Each record answers:

- **Context** — where the work came from
- **Objective** — what we were trying to understand or accomplish
- **Work performed** — what was actually done
- **Result** — what happened
- **What was learned** — the technical takeaway
- **What remained** — incomplete or unverified parts
- **Evidence** — what supports the record
- **Publication status** — what can safely be made public

## Evidence standard

The repository deliberately separates:

- **studied** from **practiced**
- **observed** from **validated**
- **candidate** from **confirmed**
- **planned** from **completed**
- **assistant-generated material** from **user-executed work**

A security observation is not presented as a vulnerability unless it was actually validated.

Bug-bounty material is not published until the relevant program/disclosure conditions are known.
